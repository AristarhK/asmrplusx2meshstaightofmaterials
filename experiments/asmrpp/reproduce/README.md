# Восстановленный запуск ASMR++

Комплект сохраняет найденные на Ubuntu исходники, конфигурацию и обученную
модель. Проверен один эпизод Poisson из четырёх уточнений без обучения.
Это воспроизведение case 0 из исторического CSV, а не новый benchmark.

## Запуск в существующем окружении

Из корня исследовательского репозитория:

```bash
python3 experiments/asmrpp/reproduce/reproduce.py --verify-only
conda run --no-capture-output -n ASMRpp_cpu python -B \
  experiments/asmrpp/reproduce/reproduce.py \
  --output experiments/asmrpp/runs/my_recovered_case0
```

Первой команде достаточно стандартной библиотеки Python. Для второй требуется
существующее CPU-окружение Python 3.10 с зависимостями ASMR++. Скрипт ничего
не устанавливает. Каталог `--output` должен быть новым; существующие файлы
и завершённые результаты не перезаписываются.

Умолчания: seed 123, evaluation environment 1, λ = 0.001274, один CPU-поток.
Изменение seed, среды или λ отключает сравнение с историческим case 0.
Время текущего запуска не сравнивается со старым измерением.

## Что делает проверка

1. Проверяет размеры и SHA-256 комплекта до загрузки модели.
2. Распаковывает и проверяет каждый исходный файл в новом `output/runtime`.
3. Копирует конфигурацию, checkpoint, нормализатор и архитектуру в изолированный runtime.
4. Загружает PPO штатным загрузчиком upstream, переводит policy в eval и выполняет
   один эпизод. Конструктор и запуск соответствуют прежнему скрипту сравнения;
   методы обучения не вызываются.
5. Сохраняет сетки/решения, trace CSV, лог, рисунок и JSON-отчёт. Сравнивает N,
   вершины и error на всех пяти состояниях; проверяет неизменность state_dict сети.
6. Повторно проверяет целостность исходного комплекта.

`runtime/` и `cache/` исключены из Git: они воспроизводятся из сохранённых входов.
`_get_remaining_error()[0]` пока обозначен как `legacy_normalized_reference_error`:
значению не приписывается норма L2/H1/energy без отдельного аудита определения.
