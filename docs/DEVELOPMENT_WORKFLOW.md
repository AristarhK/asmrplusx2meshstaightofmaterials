# Общий проект Codex, Ubuntu и Windows/ANSYS

Единый репозиторий:
https://github.com/AristarhK/asmrplusx2meshstaightofmaterials.
Текущий приоритет — прочностной расчёт бака трансформатора для темы ЭРСО.
Код, конфигурации, инструкции и решения сохраняются здесь, чтобы продолжать
работу из Codex на Windows с реальной установкой ANSYS.

## Роли сред

| Среда | Работа | Сохраняемый результат |
| --- | --- | --- |
| Codex cloud | Разработка, документация и проверки без ANSYS | Коммит, состояние синхронизации, выполненные проверки и ограничения. |
| Ubuntu | Целостность ASMR++, при наличии восстановленного окружения — отдельно согласованный inference | Манифест, веса, config, окружение и новые результаты без перезаписи старых. |
| Windows с ANSYS | Поиск старого подключения, проверка установки/лицензии, механическая модель и два расчёта с разной сеткой | Проверенные скрипты, параметры модели, экспорт сетки/полей и сравнение. |

При новой задаче читать AGENTS.md, README.md, docs/WINDOWS_HANDOFF.md,
docs/ERSO_ANSYS_SCOPE.md и docs/ASMR_REPRODUCIBILITY.md. Затем проверять реальные
файлы, ветку и HEAD. Имя папки `research-hub` — соглашение, не доказательство
местонахождения проекта. Облачная среда не предоставляет автоматически доступ
к диску Windows или лицензии ANSYS.

## Передача через GitHub

Актуальная инструкция получения ветки `repro/recover-asmr-runtime`, обновления
существующей копии, проверки SHA и поиска Windows-скрипта:
[WINDOWS_HANDOFF.md](WINDOWS_HANDOFF.md). После локального коммита публикация
выполняется явным `git push origin HEAD:refs/heads/repro/recover-asmr-runtime`.
Не смешивать её с обновлением `main`, force-push или слиянием PR.

Получение файлов и запуск `--verify-only` не устанавливают научное окружение.
Комплект inference ранее проверен в существующем Linux CPU-окружении ASMRpp_cpu;
его создание с нуля и запуск на Windows не подтверждены. API управления ANSYS
выбирается только по фактической установке и найденному Windows-проекту.

## Ближайший общий рубеж

Python решает одну фиксированную модель ANSYS на двух сетках и сохраняет
N/DoF, качество сетки, перемещения, выбранные напряжения, реакции и времена.
Материалы, нагрузки, закрепления, геометрия и solver settings остаются одинаковыми.
Различие двух решений — чувствительность к сетке, а не ошибка относительно
точного решения. Нейросетевая стратегия подключается после проверки этого цикла
и отдельного исследования переноса Poisson → упругость.

Машинные пути, локальные модели и scratch-расчёты хранить в игнорируемом `.local/`.
Отобранные результаты публиковать отдельно с разрешёнными исходными данными,
метаданными и контрольными суммами. Не коммитить окружения, кэши, runtime и секреты.
