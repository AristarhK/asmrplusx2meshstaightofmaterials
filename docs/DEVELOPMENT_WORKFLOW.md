# Общий проект Codex, Ubuntu и Windows/ANSYS

Единый репозиторий проекта:
https://github.com/AristarhK/asmrplusx2meshstaightofmaterials.
Код, конфигурации, инструкции и принятые решения сохраняются в нём так,
чтобы к работе можно было вернуться из Codex на Windows и получить файлы
для локального запуска в ANSYS.

## Роли сред

| Среда | Работа | Сохраняемый результат |
| --- | --- | --- |
| Codex с этим GitHub-репозиторием | Разработка кода, тесты без ANSYS, подготовка изменений | Ветка и PR с кодом, инструкциями и проверками. |
| Ubuntu | Восстановленный ASMR++, подготовка и оценка моделей | Веса, config, окружение, протоколы и новые результаты. |
| Windows с ANSYS | Автоматизация и выполнение механической модели | Версионируемые скрипты ANSYS, экспорт сетки/полей и отчёты расчёта. |

Долговременный контекст проекта хранится в docs и коде, а не только
в сообщениях отдельных задач Codex. При открытии новой задачи читать
AGENTS.md, README.md и docs/ERSO_ANSYS_SCOPE.md, затем состояние реализации
и результаты проверок в остальных документах.

## Получение проекта на Windows

PowerShell, первый checkout:

```powershell
git clone https://github.com/AristarhK/asmrplusx2meshstaightofmaterials.git research-hub
Set-Location research-hub
```

Обновление существующей копии после объединения PR:

```powershell
Set-Location C:\path\to\research-hub
git pull --ff-only origin main
```

Если нужные изменения пока находятся в PR, выбрать его head-ветку в Codex
или получить её в локальном Git. Для текущего восстановления:

```powershell
git fetch origin
git switch --track origin/repro/recover-asmr-runtime
```

В качестве альтернативы можно скачать ZIP выбранной ветки со страницы GitHub.
Для последующих обновлений удобнее Git checkout.

## Граница текущей проверки

Комплект `experiments/asmrpp/reproduce/` проверен в существующем Linux CPU-
окружении ASMRpp_cpu. Он сохраняет модель и её происхождение, но его окружение
не считается проверенным на Windows. Реализация управления ANSYS и переноса
политики на упругость — следующая часть прикладного проекта.

Windows-скрипты должны храниться в этом же репозитории и использовать
конфигурируемые пути к установленному ANSYS и модели. Интерфейс автоматизации
выбирается после восстановления прежнего Windows-проекта пользователя.
До этого не заявляется совместимость с конкретным API или версией ANSYS.

Для обмена между расчётом и стратегией адаптации фиксируются сетка, единицы,
идентификаторы элементов/граней, материалы, граничные условия, поля решения
и рекомендации сгущения. Одна постановка должна воспроизводиться после
перестроения сетки; результаты каждого запуска получают отдельный каталог.
